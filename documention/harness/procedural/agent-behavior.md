# Agent 行为规则

> 跨任务可复用的决策原则。每次会话必加载。来源事件见 episodic/ 对应复盘。

## 1. 仓库惯例 ≠ 正确默认：跟随惯例前先检查是否已有新基础设施

- 仓库的"现状写法"可能只是**存量债**，不是新代码的许可。跟随惯例前先判断：
  这个模式是不是已经被更新的基础设施取代了（如 i18n 管线已接好但存量页面
  全是硬编码——0 处 `t()` 是债，不是硬编码的理由）。
- 判据：动手前看 `semantic/` 对应域文件 + 近期 plan 文档，确认"惯例"与
  "基础设施"谁更新。基础设施更新 → 新代码走新管线。

## 2. 用户问"你是不是会 X"是在检验默认行为，不是闲聊

- 这类问题（"你会不会硬编码文案？"）的信号：用户在测试 agent 的默认路径。
  正确反应是**诚实回答默认行为 + 立即把正确默认固化成规则**（写进本目录），
  而不是口头保证"我会做对"。
- 知识不能靠 agent"碰巧读到"，要进必加载清单或 guardrail（见 harness README 维护规则）。

## 3. 当场复盘信号：用户的"为什么/是不是绕弯"质疑要先停后答

- 用户对已发生的行为抛出"为什么这么做/影响什么"时，先给出**基于证据的回答**
  （git log、文件、时间线），再谈修复。不要跳过解释直接改代码——那会让用户
  失去对变更的可见性。
